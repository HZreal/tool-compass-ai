# AI Scenery 运维手册

本手册描述仓库支持的操作边界。测试通过不等于线上验收通过；每次实际操作均应在 `project-status.md` 记录日期、版本、执行人、命令/入口、结果与剩余风险。

## 环境与数据归属

- 生产托管由 Sites 管理，`.openai/hosting.json` 的 `d1: "DB"` 表示绑定名。它不是 Cloudflare 数据库 ID。
- `tests/e2e/wrangler.json` 内的全零占位 ID 仅供本地 Miniflare。不得拿它执行远程导出、远程迁移或恢复。
- 不能假设站点拥有者拥有独立 Cloudflare 账户、真实 database ID 或 Wrangler 远程权限。生产迁移与绑定由 Sites 发布链处理；备份优先使用受管理员鉴权保护的应用级 JSON 接口。
- 本地 `.wrangler/state` 和线上 D1 是不同数据库。本地重置、迁移和测试不能证明线上数据已更新。
- 保持站点私有；只有在用户明确授权后才改变公开性。

## 本地启动与质量门禁

使用 Node 22.13.0 或更高版本。先停止本工作树中的开发服务，避免多个 Miniflare 实例争用本地 SQLite；不得停止其他项目的进程。

```sh
npm ci
npx wrangler d1 migrations apply DB --local --config tests/e2e/wrangler.json --persist-to .wrangler/state
npm run db:seed:local
npm run dev
```

`db:seed:local` 是本地目录数据重置操作，不是线上迁移。需要保留本地编辑记录时不要执行；先导出备份。迁移、种子写入和开发服务必须顺序运行，等待前一步真正退出。

开发服务停止后运行：

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
```

`npm test` 包含生产构建与 Node 测试；`test:e2e` 运行整个 `tests/e2e` 目录，覆盖桌面与 360px、搜索/过滤/详情、五个导航入口、Tab 焦点和 axe 的标签/对比度检查。Playwright 使用本机 Chrome。首次运行应确认 Chrome 已安装；若使用 Playwright 自带浏览器，需要在配置中明确改用该浏览器后再安装。自动无障碍检查不替代屏幕阅读器人工体验。

端到端启动脚本会初始化并重置本工作树的本地 D1 目录数据。不要在需要保留的数据环境直接运行；测试前备份，且不要并行执行种子或迁移。

## 数据库迁移与发布

1. 修改 `drizzle/schema.ts` 后生成迁移，审阅新增 SQL；保留已发布迁移，禁止重写历史迁移掩盖生产差异。
2. 在本地副本应用所有迁移并运行完整测试。涉及列变更、关联表或 FTS 的迁移，额外确认原有工具、投稿、审计和搜索结果未丢失。
3. 发布前下载一份当前生产备份，记录格式版本、导出时间和各表行数，安全保存于仓库之外。
4. 构建会将 `.openai/hosting.json` 和 `drizzle` 迁移打包到 `dist/.openai/`。经 Sites 既有项目发布流程部署，确认发布日志中的绑定和迁移结果；不要自行虚构 Wrangler 远程命令。
5. 保持私有访问，记录部署版本/预览链接。逐项检查首页、目录组合筛选、搜索、详情、投稿以及管理员创建草稿、发布、归档、审核流程。
6. 失败时保留日志和发布版本，先查明是构建、绑定、迁移还是业务错误。代码回退不自动回退数据库；不要直接运行破坏性逆迁移。

## 管理员密钥与身份

通过 Sites 项目的 secret 管理能力设置服务端 `ADMIN_USER_ID`，值必须是已确认管理员的 ChatGPT user ID，不是邮箱、显示名称或 API key。不得写入仓库、前端环境变量、日志和公开文档。

更换管理员时先核对新 ID，再更新 secret 并按控制面的要求重新发布/激活。分别验证：未登录请求被拒绝、非管理员被拒绝、指定管理员成功。请求身份头必须来自 Sites 可信认证边界；本地伪造头不能作为线上鉴权证明。

localhost 登录 cookie 仅用于本地开发。不要把本地自动登录成功当作线上 ChatGPT 登录成功；生产域名不应接受本地 cookie 回退。

## 备份、恢复与演练

管理员登录后访问 `/admin/operations`。`GET /api/admin/backup` 返回完整 JSON 下载附件；`POST /api/admin/backup` 接收以下结构：

```json
{
  "confirmation": "RESTORE AI SCENERY",
  "backup": {
    "format": "ai-scenery-backup",
    "version": 1,
    "schemaVersion": 8,
    "tables": {}
  }
}
```

这里的空 `tables` 仅示意包装结构，不是可恢复备份；`backup` 必须使用完整、未删改的导出对象。接口当前限制为 5 MB、所有表合计 5000 行；超过限制应停止并设计受控的大库备份方案，不要拆分覆盖恢复。`schemaVersion: 8` 是应用备份兼容版本，不是 SQL 迁移文件的数量或最后一个文件序号。格式版本或 schemaVersion 不匹配时先确认目标部署和迁移版本，不得手改版本号强行导入。

应用级备份必须覆盖完整业务数据，包括工具、分类、场景、标签、关联、投稿、外跳事件和审计；FTS 是派生索引，不应作为唯一可恢复副本。备份含用户提交内容与运营审计，请按敏感数据处理，不提交 Git、不公开分享。

恢复前必须确认目标环境，暂停编辑与投稿写入，先再导出目标当前数据以便回退。恢复为覆盖性操作，需得到明确授权，不能仅因为存在一个备份文件就执行。服务端应在写入前校验 JSON 格式版本、字段、主键、外键和规模，在同一 D1 批次事务中恢复，并重建搜索派生数据。成功后重新导出，对照表行数和关键记录；确认关联、搜索、状态可见性、管理员权限及审计都有效后再恢复运营。

建议每次结构迁移前备份，每月进行一次非生产恢复演练：

1. 从源环境导出 JSON，记录导出时间和 SHA-256；保留文件原件。
2. 在独立、可清空且已应用匹配迁移的测试 D1 中恢复，绝不在唯一生产库试验。
3. 确认非法 JSON、重复主键、缺失关联等无效文件被拒绝且原数据不变；确认无权限用户不能导出或恢复。
4. 比较业务记录总数、已发布/草稿/归档数、投稿状态和审计记录；执行别名与标签搜索，点击详情和官网跳转。
5. 记录恢复耗时、恢复点时间、验证证据及发现的问题。未实际演练时必须写“未演练”，不能把具备接口写成备份已可恢复。

应用 JSON 备份不包含 Sites secrets、平台认证设置或发布版本；这些需分别维护受控记录。若未来获得真实 Cloudflare 权限，可另行制定平台级导出方案，但不能用它替代本手册已验证的流程。

## 缓存与日常维护

当前公开 GET 使用 `no-cache, max-age=0, must-revalidate`；管理员数据、备份与写接口为 `no-store`。每次读取重新查询 D1，保证后台编辑后即时可见。5分钟缓存是尚未实施的性能优化。写入后验证受影响的目录、详情与搜索，不能把响应头中的“清理标签”当成真实缓存失效。

恢复最多4999行，为新增的一行恢复审计预留空间，导出最多5000行。上述 schemaVersion=8 是应用备份契约版本，与迁移文件数不一一对应。

新增线上库依次应用 0006、0007、0008 后，使用唯一管理员登录 /admin/operations 执行“导入 2026-09-05 核验资料”。这是一次性受鉴权的数据操作，不是 schema migration，也不会由公开页面访问触发；先完成导入才能导出具有完整标签关系的旧库备份。

每月检查工具官网、定价、平台、地区可用性及核验日期；审核投稿、清理失效精选并保留编辑说明。核验需要查看官方来源，不要只更新时间戳。定期执行 `npm audit` 评估依赖风险；不要未经测试运行 `npm audit fix --force`。将运行结果和未解决风险补充到项目状态文档。
