# Tool Compass AI MVP 产品设计文档

## 1. 产品定位

Tool Compass AI 是一个面向中文用户的 AI 工具发现平台，覆盖国内外最具价值、应用广泛且已成熟可用的产品。它不以“收录数量”作为首要价值，而以“按真实任务快速找到值得使用的工具”为目标。用户应能在 30 秒内完成：表达需求、缩小选择范围、理解工具是否适合自己、进入官网试用。

首批目标用户为内容创作者、知识工作者与轻度 AI 使用者；开发者工具保留入口，但不是首版内容重心。

## 2. MVP 目标与边界

### 成功标准

- 用户从首页、分类页或搜索结果页点击工具官网的比例可被衡量。
- 编辑可以不依赖开发人员完成工具的新增、修改、下架与推荐排序。
- 用户能够通过表单推荐新工具或指出资料错误。

### 不在 MVP 范围内

- 用户账号、跨设备收藏与个人推荐算法。
- 评论、打分、问答社区与工具排行榜。
- 自动抓取、自动评测、实时新闻流与多语言内容。
- 付费订阅、广告交易、开发者 API 与应用内调用第三方 AI。

## 3. MVP 核心功能需求

### F1：首页与任务入口

首页提供一个主搜索框、精选工具、热门分类与“我想要完成什么”场景入口。场景入口首批包括：写文章、做 PPT、生成图片、制作视频、提升办公效率、辅助编程。每个入口进入已预筛选的工具列表。

### F2：工具目录、分类与筛选

工具目录按八个一级分类组织：聊天与问答、写作与翻译、图像与设计、视频与音频、办公与效率、编程与开发、智能体与自动化、学习与研究。分类页支持关键词搜索及基础筛选：免费/可试用、国内/海外、网页/桌面/移动端。筛选结果可分享为 URL。

### F3：站内搜索

搜索覆盖工具名称、别名、简介、任务标签与分类。输入为空时展示搜索建议；无结果时推荐相近分类、场景和提交工具入口。首版采用关键词匹配，不承诺语义检索。

### F4：工具卡片与详情页

卡片必须显示名称、简短用途、标签、定价状态、编辑精选标记和最后核验日期。详情页增加适合谁、典型用途、语言/平台、官网跳转、相似工具与编辑说明。所有外链跳转记录匿名点击事件。

### F5：收录与纠错

提供无需登录的表单，支持“推荐一个新工具”和“纠正现有资料”。表单提交后进入待审核队列；用户看到已收到的确认状态，但不承诺上线时间。

### F6：编辑运营后台

编辑可管理分类、场景、工具、标签与首页精选顺序；工具有草稿、已发布、已下架三种状态。发布前需填写官网链接、简介、分类、至少一个场景标签、定价状态和核验日期。

## 4. 内容数据模型

工具记录包含：名称、别名、slug、logo/封面、简介、官网 URL、分类、场景标签、功能标签、语言、平台、地区、定价状态、精选等级、编辑推荐理由、核验日期、发布状态、创建与更新时间。场景记录包含名称、描述、封面色彩、排序及关联工具。

## 5. 信息架构

```text
首页
├─ 全站搜索
├─ 场景入口
├─ 分类目录
├─ 精选工具
└─ 收录/纠错
分类与搜索结果页
└─ 工具详情页 → 官网外跳
编辑后台
├─ 工具管理
├─ 分类与场景管理
├─ 首页精选
└─ 提交审核
```

## 6. 关键体验与规则

- 每张工具卡只回答一个问题：它能帮我完成什么；避免堆满参数和标签。
- “编辑已核验”与核验日期必须可见，过期信息在后台优先提醒复核。
- 外部跳转始终在新标签页打开，并标识为官网链接。
- 移动端优先保证搜索、场景入口和卡片浏览；侧栏筛选改为抽屉。
- 可访问性要求：可键盘操作、图片有替代文本、文字与背景有足够对比度。

## 7. 后续扩展路线

### P1：留存与内容质量

本地收藏、最近浏览、工具对比、同类替代品、专题合集、编辑测评文章、失效链接巡检和订阅更新提醒。

### P2：社区与个性化

登录、跨设备收藏、用户工具清单、投票与体验反馈、按角色/行业的推荐页、个人化首页。

### P3：平台能力

面向工具方的认领页、赞助展示的明确标识、开放 API、浏览器扩展、工作流模板与第三方服务集成。

## 8. 首版验收条件

首页、分类、搜索结果、工具详情、提交表单与编辑后台均可访问；至少录入 80 个经过核验的工具；任意工具官网跳转可被记录；所有主要页面在桌面与移动尺寸可正常阅读。
